## Original viewport and Input read sequence

quest_input_read.h preserves the audited native sequence:

1. Viewport requires its actual Input. Ordered elapsed other than-1 polls
   UpdateInput(0), then reloads the configured Input and output device before
   ReadInput. Post-input-1 and unordered elapsed never poll again.
2. Input observes the actual process-running capability before Actor/cache
   access. False returns without processing or scaling.
3. Acquire the real inherited all-INPUT-property cache by entry Actor Class.
   Read live keys0..254 in ascending order; each nonzero slot selects global
   output afresh and calls actual configured InputExt.Process with Hold2.
   Later keys may have been cleared by an earlier Root callback.
4. Keep20/elapsed in the original extended precision profile; equal-1 or NaN
   keeps positive zero. Multiply each actual cached FloatProperty and store
   Float through its qualified current-Actor VM reference. No clamping,
   positive-zero assignment or detached axis/Actor mirror is introduced.
5. Release lexical cache use on normal return or failure. The actual shared
   property cache/GC roots remain root-owned until normal commit or undo.

portable_input_read_host.inl binds those operations to the real current native
viewport/Input/Pawn, shared work/frame/state ledgers, source reconciliation,
InputExt/Root/current bindings and caller Execution. The explicit ordinary
FString output-device profile is selected per original global load; no raw
PE32 GLog address is claimed. Actual local Player Tick now calls this service
for both pre-input and post-input; PlayerInput/PlayerTick retain their original
checked-event ordering. Pose/world aim and legacy motion/fire handover remain
separate required work.
