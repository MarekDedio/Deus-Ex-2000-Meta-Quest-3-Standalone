The first owned integration attempt exposed a32MiB admission failure caused by
cloning the entire qualified/folded namespace for nine additions. The corrected
algorithm stages only new alias/Package nodes, resolves staged/live identities
separately, reserves destination buckets and transfers nodes without allocation.
It retains the original limit. A failed reserve may retain spare dictionary
capacity, not a logical member/default/counter or UObject lookup publication;
actual hash precedence is independent of dictionary iteration/rehashing.

The exact38-package Quest bootstrap check then exposed a separate failure at
initial actual-object lookup, before this Engine phase. Its second ordered
identity tree is replaced by identity chains intrusive in the existing stable
numeric-tree nodes. The numeric tree still owns every record and supplies the
same ascending ANY_PACKAGE order; the original exact-name bucket chains and
their publication/rehash order remain separate and unchanged. Both fixed head
arrays are charged, and the same conservative per-tree-node overhead remains.
This removes an allocation per object rather than raising the32MiB limit,
excluding audio/UI objects or weakening accounting. Copy reconstructs its own
identity chains; allocation-free adoption transfers their nodes and heads;
cached-key removal never dereferences the object or its Outer.
